# 「出典つきの枠」と共通の注意書きの案（2026-11-18・実装していない）

## A. 出典つきの枠（応援割の data-fact と同じ考え方）
旅先ページの事実（料金・休館日・営業時間・年号・標高・距離など）に、公式の出典URLと確認日を付けて、検査で突き合わせる。

### データ
記事（src/data/articles/<id>.json）の節ごとに、確認できた記述だけを持つ。
```
"factSources": [
  { "節": 1, "項目": "入館料", "値": "330円", "出典": { "名称": "人吉市（人吉城歴史館 利用案内）", "url": "https://www.city.hitoyoshi.lg.jp/kanko/kankojyoho/2487137" }, "確認日": "2026-11-18" }
]
```
- 値は、節の info の行（「料金：330円」）や本文の文と同じ文字列。
- 出典の種類は、施設の公式・自治体・観光協会・公的データベースだけ（ドメインの許可リストで検査する）。民間のまとめ記事は載せない。

### 表示
- 節の info の下に、小さな1行「公式で確認: 人吉市（2026-11-18）」（リンクつき・文字は灰色・小さめ）。出典のある節だけに出る。
- 出典の無い節には何も出さない（共通の注意書きだけが効く）。

### 検査（audit に足す）
1. 数字（料金・休館日・営業時間・年号・標高・距離）を含む info の行・文は、factSources に対応があるか、そのまま（確認済みでない）なら警告として数える。削除済みなら対象外。
2. factSources の値が、節の文字列に実在する（文字列を書き換えたのに出典だけ残る、を防ぐ）。
3. 出典URLのドメインが許可リスト内。確認日が180日より古ければ警告（料金・営業時間は変わるため）。
4. 値を直したのに確認日が古いまま、を防ぐため、値の変更と確認日の更新を同じコミットで検査する（scripts/checkDeletionEdits20261118.mjs と同じ old→new 形式で記録する）。

### 工数・リスク（推測）
- 工数: データ項目・表示・検査で数日。確認作業そのもの（公式の取得）は、優先ページの試験で1ページあたり約14万トークン・約38秒。
- リスク: 出典の期限切れ（再確認の運用が必要）。出典を付けた節と付けない節で、見た目に差が出る。

## B. 全旅先ページ共通の注意書き
### 文言（2案）
- 案1（推奨）: 「料金・営業時間・休館日などは変わることがあります。お出かけ前に、各施設の公式サイトでご確認ください。」
- 案2（短い）: 「料金・営業時間・休館日は変わることがあります。公式サイトで最新の情報をご確認ください。」

### 置く場所
- 旅先ページの「◯◯のおすすめスポット」の見出しの直下に1回だけ（各節には繰り返さない）。ページの本文のうち、料金や営業時間が出てくる節の直前に読まれる位置。
- 小さめの文字（13px 前後）・灰色・1〜2行。アフィリエイトの表示（PR表記）とは別の行にし、混ぜない。
- 統合ページ（隠岐諸島など）は、各見出しの前ではなく、見出し群の先頭に1回。
- 診断（/quiz/）の結果ページ・応援割ページには置かない（応援割ページは data-fact の枠が既にある）。

### 理由と注意
- 「必ず」「保証」は書かない。事実の誤りがあることを前提にした書き方にしない（「変わることがあります」まで）。
- 出典つきの枠（案A）を作った場合は、枠のある節に「公式で確認: ◯◯（確認日）」が出るので、注意書きは「枠の無い記述は、お出かけ前に公式サイトで確認」まで書き足す。
